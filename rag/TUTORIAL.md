# RAG 检索优化教程

这份教程讲一件事：**怎么判断公告检索准不准，以及怎么把它调准**。全部结论都是在这套代码上实测出来的，不是理论。

---

## 一、先记住一句话

> **相似度距离的绝对值没有意义。要看的是 gap——"最好的那条"比"随便抽一条"好多少。**

如果你只记一件事，记这个。

---

## 二、为什么距离总是"凑得很紧"

你在 CLI 里会看到这样的输出：

```
[1] 距离=0.400  《2025年度股东会决议公告》
[2] 距离=0.427  《2025年度股东会会议资料》
[3] 距离=0.465  《2025年度权益分派实施公告》
[4] 距离=0.470  《2025年度股东会会议资料》
```

0.400、0.427、0.465、0.470——挤在一起。**这是正常的，不是 bug**，两个原因：

**1. 句向量模型有"各向异性"**

我们用的 `bge-small-zh-v1.5` 会把所有中文句子的向量塞进空间里一个很窄的圆锥区域。结果就是：任意两段文本的余弦距离天然就偏高（0.3~0.8），天然就接近。这不是茅台的锅，也不是你代码写错了。

**2. 语料是同源的**

642 块全是**同一家公司**的中文正式公文。"本公司""董事会""根据《公司法》""特此公告"这些词到处都有，任意两块本来就长得像。

所以：**看到 0.45 不用慌，它既不代表"很相关"，也不代表"不相关"。** 这个数字只有跟同一次检索里的其他数字比才有意义。

### 那看什么？看 gap

```
gap = 全库距离中位数 − top-1 距离
```

翻译成人话：**"最相关的那条"，比"闭着眼睛随便抽一条"，好了多少？**

实测数据（贵州茅台）：

| 问题 | top-1 距离 | 中位数 | **gap** | 判断 |
|---|---|---|---|---|
| 2025年度每股现金分红是多少？ | 0.313 | 0.601 | **0.288** | ✅ 有效 |
| 大股东有没有减持或增持？ | 0.503 | 0.656 | **0.153** | ❌ 失效 |

分红那个问题，top-1 比中位数好了 **0.288**——检索真的把答案挑出来了。
减持那个问题只好了 **0.153**——排在前面的和随机抽的差不多，等于没检索。

**经验档位**（针对本项目的中文公告语料）：

| gap | 含义 |
|---|---|
| > 0.20 | 检索有效，可以信 |
| 0.15 ~ 0.20 | 勉强，可能漏掉真信号 |
| < 0.15 | 基本是碰运气，别信 |

CLI 里跑 `diagnose` 会直接把这个算给你。

## 三、实测发现的两个真问题

### 问题 1：定期报告是噪音池

茅台 30 篇公告切出 642 块，其中：

| 公告 | 字数 | 约切出多少块 |
|---|---|---|
| 2026年半年度报告 | 117,892 | **~368** |
| 2026年第一季度报告 | 10,717 | ~34 |
| 2026年半年度报告摘要 | 2,468 | ~8 |

**三份定期报告 = 410 块 = 全库的 64%。**

这些几百页的报告里，股东持股表、财务报表被切成一堆数字碎片，字面上全是"股东""增持""减持"，但语义上是垃圾。它们把真正一句话说清楚的临时公告挤出了排行榜。

### 问题 2：向量检索匹配"主题"，不匹配"答案"

这个更本质。问"大股东有没有减持或增持？"，正确答案《关于回购股份实施结果暨股份变动的公告》里白纸黑字写着：

> 公司控股股东中国贵州茅台酒厂（集团）有限责任公司**累计增持1,274,234股**公司股票，占公司总股本的0.1018%，**未减持**公司股票。

含"股东""增持""减持"三个词，**纯向量检索却连 top-10 都进不去**。top-10 被谁占了？

- 《关于召开2025年度股东会的通知》
- 《独立董事候选人声明与承诺（郭田勇/王鑫/盛雷鸣）》
- 《北京市金杜律师事务所…法律意见书》

这些**只含"股东"二字**、不含"增持/减持"，主题相关但答非所问。

**向量是"意思相近"，它觉得"关于股东的通知"和"大股东有没有减持"意思相近。**

## 四、四个优化杠杆

### 杠杆 1：过滤定期报告（去掉 64% 噪音）

建索引时丢弃半年报/年报/季报。判定用**精确子串**而不是"年度"这种宽泛词，否则会误伤《关于调整2025年**年度**利润分配方案…》《2025年**年度**权益分派实施公告》这类真信号。

代码在 `rag/fetch.py:is_regular_report`。默认开启。

**实测效果**：642 块 → **231 块**。分红问题 gap 0.288 → 0.297（略升，没退化）。

（再加上杠杆 3 的独董文书过滤，最终落到 **195 块**。）

### 杠杆 2：混合检索（这是关键的一招）

**同时跑两路检索，再把结果合并**：

| | 匹配什么 | 强项 |
|---|---|---|
| 向量检索 | 意思 | "回购" ~ "股份购回" |
| 关键词检索（BM25） | 字面词 | "增持""减持"这种精确词 |

两路各自排名，用 **RRF（倒数排名融合）** 合并。RRF 只看"排第几"，不需要把两种分数归一化，也不用调权重——这是工业界混合检索的默认做法。

**实测效果**（就是上面那个减持问题）：

| | 纯向量 top-5 | 混合检索 top-1 |
|---|---|---|
| 命中 | 股东会通知 / 法律意见书 / 独董声明×2 / 会议资料 | **《回购股份实施结果暨股份变动的公告》** |
| 答案在不在 | ❌ 一条都没有 | ✅ **第 1 名** |

而且注意 BM25 得分给了向量距离给不出的**分辨力**：

```
[1] 关键词得分=10.57  《回购股份实施结果暨股份变动的公告》   ← 答案
[2] 关键词得分= 2.07  《关于召开2025年度股东会的通知》
[3] 关键词得分= 1.97  《独立董事候选人声明与承诺》
```

**10.57 vs 2.07，差 5 倍。** 对比向量距离 0.5306 / 0.5466 / 0.5480 全都挤在一起——这就是"紧凑度"问题的正解：不是想办法把距离挤得更紧，而是**换一个能分清好坏的信号**。

代码在 `rag/lexical.py`（BM25）+ `rag/query.py`（融合）。

### 杠杆 3：过滤独董模板文书

《独立董事候选人声明与承诺》（三位候选人各一份）、《独立董事提名人声明与承诺》、《独立董事述职报告》——**证监会统一模板**，通篇"本人不存在……""提名人认为……"，没有一条本公司特有的信息。

它为什么能上榜？看实测的词频：

| 文书 | 字数 | 增持 | 减持 | 控股股东 | 股东 |
|---|---|---|---|---|---|
| 候选人声明（王鑫） | 2563 | **0** | **0** | 5 | 14 |
| 候选人声明（郭田勇） | 2527 | **0** | **0** | 5 | 14 |
| 候选人声明（盛雷鸣） | 2527 | **0** | **0** | 5 | 14 |
| 提名人声明 | 2362 | **0** | **0** | 4 | 11 |

**一个"增持/减持"都没有，却有 53 个"股东"。** 它纯粹是靠"股东"这个通用词挤进来的——字面命中，语义为零。删掉它属于纯赚。

**实测效果**：231 块 → **195 块**（去掉 27 块声明 + 9 块述职报告）。最实在的一处改善是**风险那个问题**：

| 问"有没有诉讼、仲裁、行政处罚或重大风险提示？" | 融合第 1 名 |
|---|---|
| 过滤前 | 《独立董事提名人声明与承诺》 ❌ |
| 过滤后 | 《关于贵州茅台集团财务有限公司的风险评估报告》 ✅ |

其余问题的第 1、2 名**完全没动**，只是把被模板文书白占的坑位让了出来。

判定规则在 `rag/fetch.py:is_director_boilerplate`，用**精确子串**（候选人声明/提名人声明/述职报告）而不是"独立董事"——否则会误伤《关于独立董事**辞职**的公告》，那是有实质信号的（独董辞职常牵出治理问题）。

### 杠杆 4：每份公告最多贡献 2 段

防止某一份公告把 8 个名额占满、挤掉别的信号。代码在 `rag/service.py:_MAX_PER_TITLE`。

## 五、为什么必须用 jieba 分词

这里踩过一个坑，值得记下来。

**最初想零依赖**：不装分词库，用**字符二元组**当词。"减持"→`{减持}`，看起来能行。

**但二元组会把跨词边界切出垃圾**：

```
"减持或增持"  →  {减持, 持或, 或增, 增持}
                  ↑好的           ↑垃圾
```

垃圾词的问题在于——**它们的 df/idf 和答案词完全一样**：

```
减持  df=1  idf=5.04   ← 答案词
增持  df=1  idf=5.04   ← 答案词
没有  df=1  idf=5.04   ← 垃圾（提问措辞）
或增  df=1  idf=5.04   ← 垃圾（跨词碎片）
东有  df=1  idf=5.04   ← 垃圾（"股东有没有"的碎片）
```

语料只有两百来块，一个词出现 1 次就是 df=1。**统计量根本分不出"减持"和"或增"**。实测症状：BM25 冠军变成《法律意见书》，因为它碰巧含"没有"和"或增"。

**换 jieba 之后**：`大股东有没有减持或增持？` → `大股东 | 有没有 | 减持 | 或 | 增持`，虚词进停用词表，剩下 `{大股东, 减持, 增持}` 全是有意义的词。BM25 冠军立刻变成正确答案，得分来源是 `增持(4.81)、减持(4.81)`——**正是答案词**。

**教训**：中文用二元组做关键词检索，在小语料上会被跨词碎片污染；老老实实用分词库。

## 七、什么时候需要 `--keep-reports`

默认**丢弃**定期报告。什么时候需要捡回来？

**只有你要查财务数字（营业收入、净利润、资产负债率）的时候。** 因为那些数字只在定期报告里。

```bash
python -m rag.cli index --code 600519 --keep-reports       # 重建，保留定期报告
python -m rag.cli context --code 600519 --keep-reports     # 相应地查的时候也要带上
```

注意：**建库和查询的口径必须一致**。代码会自动检查——如果你用 `--keep-reports` 建了库，下次不带这个参数查询时，它判定"口径不符"会自动重建一次。这是故意的，防止你拿错口径的库去查。

## 八、为什么不用 reranker

你可能会听说"加个 reranker 重排效果更好"。**理论对，但这个场景不划算。**

- 中文 reranker（如 `bge-reranker-base`）约 **1.3GB**，首次要从镜像下载
- 每检索一次都要跑一遍 cross-encoder，**流水线本来就要跑 6 个问题**，延迟叠加明显
- 而收益呢？我们**已经用零额外成本的手段**（过滤 + BM25）把目标文档从"榜上无名"提到了"第 1 名"

**先把手上的牌打好。** 等哪天发现混合检索仍然漏，再考虑上 reranker。

## 十、插曲：一个反直觉的发现——别顺手删《法律意见书》

独董文书删完，你一定会盯上另一类同样没营养的东西：**《…股东大会之法律意见书》**——律师证明"本次会议召集、召开程序合法"，通篇是表决票数，零投资信息。它当时占着减持问题的第 2、4、5 名。

顺手一起删掉？**实测会变差。**

```
只删独董文书（195 块，保留法律意见书）：
  [1] 关键词=11.85  《回购股份实施结果暨股份变动的公告》   ← 正确答案，第 1 名 ✅

再把法律意见书也删掉（176 块）：
  [1] 关键词= 2.55  《关于召开2025年度股东会的通知》        ← 错答案，升到第 1 名 ❌
  [2] 关键词=10.29  《回购股份实施结果暨股份变动的公告》     ← 正确答案，掉到第 2 名
```

**为什么删噪音反而把排名搞坏了？** 因为 **RRF 是"排名制"，不是"分数制"**：

```
RRF 得分 = 1/(60 + 向量排名) + 1/(60 + 关键词排名)
```

它只看"你排第几"。法律意见书在**向量那一路排名很高**（它在 top-1 附近），删掉它之后，排在它下面的《股东会通知》**名次一下往前跳了很多**，白捡一大笔 RRF 分；而《回购》在关键词那一路本来就是第 1 名，**名次没法再往前**，拿不到这份红利。于是《股东会通知》反超了。

**教训**：在排名融合的系统里，**删掉一个文档对剩下文档的影响是不均匀的**——谁排在被删文档后面，谁就白捡便宜。所以"看着像垃圾就删"是危险的，**每次删都要实测 top-1 有没有变**。这也是为什么本项目的过滤规则全都写死在代码里、附带一句实测结论，而不是做成一个"用户随便勾"的开关。

（顺带一提，《法律意见书》在流水线里其实已经被"每份公告最多出 2 段"限制住了，危害有限。所以最省事的做法就是**留着它**。）

## 十一、已知的遗留问题

诚实记录，下次可以继续改进：

1. **《股东会会议资料》《股东会通知》《法律意见书》仍占着大量坑位**——这三类加起来 110 块，是 195 块里的 **56%**。但**不能盲删**：会议资料里装着分红、回购方案的正文细节，删了分红问题就废了。要动这块得先想清楚"哪几段留、哪几段弃"，比按标题删难得多。
2. **《业绩说明会通知》是弱相关噪音**——只是通知什么时候开会。但**也删不得**：实测删掉它之后，"有没有业绩预告"这个问题就没有任何文档可答了（这批公告里确实没有正式业绩预告）。**没有更差的答案，就不要把现有的答案删掉。**
3. **gap 阈值是经验值**——0.20/0.15 这两个线是在茅台这份语料上试出来的，换股票池可能要重新校准。
4. **`cninfo_announcements` 这个旧集合（642 块）没清**——是早期 CLI 建的，带定期报告噪音。现在流水线只用 `announcements_{code}`（195 块，口径 = 丢定期报告 + 丢独董文书），留着旧集合只会在不带 `--code` 时误导。建议删掉或重建。

## 十二、口径会变，所以索引会自动重建

新增过滤规则 = **建库口径变了**。老库是按老口径切的块，继续用它会让你以为"改了代码没生效"。

所以 `rag/index.py` 把口径写进了集合的 metadata：

```
skip_regular_reports: True   # 丢弃定期报告
drop_director_docs:   True   # 丢弃独董模板文书
```

`collection_exists()` 每次比对这两个键：**对不上就判定过期、自动重建一次**。老库没有 `drop_director_docs` 这个键，取默认值 `False`，与期望的 `True` 不符 → 触发重建。你不需要手动删向量库。

**副作用**：升级后第一次分析会重跑一遍建索引（茅台约 3 秒，PDF 有缓存；没缓存则要重下）。之后照旧走缓存。
